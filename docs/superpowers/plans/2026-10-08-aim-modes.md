---

**Goal:** Add selectable ASSIST and CURSOR aim modes and move the charge shot to a held right-hand pinch so the left hand can fly while charging.

**Architecture:** Pure rules go in `HandHero.Core` with EditMode tests:
- `PinchTrigger` — fire edge, hold level, fist suppression
- `AimAssist` — angle and radius target selection with hysteresis
- `AimCursorModel` — relative cursor drag

`HandInputData` gains `PinchHeld`, `AimClutchHeld` and `AimClutchDelta`. `PointingBeamController` resolves the aim point per mode and runs the charge from the pinch hold. Scene wiring is done only by `HandHeroSceneBuilder`.

**Tech Stack:** Unity 6000.6.4f1, C#, XR Hands 1.9, NUnit EditMode tests, TextMeshPro, Input System.

**Spec:** `docs/superpowers/specs/2026-10-08-aim-modes-design.md`

## Global Constraints

**Values**
- Pinch thresholds keep their names and defaults: `pinchFireThreshold` 0.8, `pinchResetThreshold` 0.5.
- Aim-hand fist uses the existing `grabThreshold` 0.7 / `releaseThreshold` 0.45.
- `fistSuppressTime` = 0.15 s. `ChargeParams.Default` is unchanged (min 0.3 s, max 1.5 s).
- `chargeMoveSpeedMultiplier` = 0.6.
- `assistAngle` 8°, `assistReleaseAngle` 11°. Bot controller `assistAngle` = 0.
- `cursorPositionScale` 60; `cursorAssistRadius` 2.5 m, `cursorAssistReleaseRadius` 3.5 m.
- PlayerPrefs key `HandHero.AimMode` (0 = Assist, 1 = Cursor), default Assist.
- Menu labels: `AIM: ASSIST` / `AIM: CURSOR`.
- Tutorial prompts:
  - ASSIST: `Point at the target with your RIGHT hand`
  - CURSOR: `Make a RIGHT fist and drag the orange marker onto the target`

**Hard rules**
- The XR Origin is never moved or rotated.
- Every gesture threshold uses hysteresis.
- Tuning knobs are `[SerializeField]` with a `[Tooltip]`.
- Never hand-edit `.unity` YAML: scenes come from `HandHero.EditorTools.HandHeroSceneBuilder.BuildAll`.
- Do not change existing tuning defaults (positionScale 60, stiffness 10, damping 5, glideDrag 0.8, …).
- Code comments in English. Commits `Area: what changed` + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Batch Unity commands need the editor closed. If `compile_check.ps1` exits 4, ask Hyun to close Unity.

**Commands**
- Compile: `powershell -NoProfile -ExecutionPolicy Bypass -File "AUTO\tools\compile_check.ps1"`
- Tests: the same command + `-Tests`
- Scene builder: the same command + `-ExecuteMethod HandHero.EditorTools.HandHeroSceneBuilder.BuildAll`

## Review Focus

1. **Charging while the aim hand drops out or the game pauses.** Expected: the charge is cancelled, with no charge shot fired into a paused frame. Owner: Task 5 (`PointingBeamController`), checked by test `ChargeCancelRuleTests` on the Core helper `ChargeInputRule`.
2. **A right fist in CURSOR mode.** Expected: dragging the marker never fires, and a pinch already closed when the fist opens does not fire until it re-opens. Owner: Task 1 tests.
3. **The assist target dies, is disabled, or the candidate list changes order.** Expected: the lock drops or follows the same object, and never jumps to another object because of an index shift. Owner: Task 2 test `SelectByAngle_CurrentMinusOne_PicksFresh` plus the identity mapping in Task 6.
4. **Re-grabbing the cursor after the hand moved, and a cursor at the arena wall.** Expected: no jump, and the cursor stays inside bounds. Owner: Task 3.
5. **A tap shorter than the min charge time.** Expected: exactly one normal shot, no charge shot, and the hero is not slowed after release. Owner: Task 1 (single edge) + Task 5 (multiplier restored on release, `ChargeInputRule` test).

- [ ] **Step 2: Run — expect a compile failure (`AimAssist` missing).** Same `-Tests` command.

- [ ] **Step 3: Implement `AimAssist`.**
  - Angle = `Vector3.Angle(ray.direction, c - ray.origin)`. A candidate is valid only when `Vector3.Dot(c - origin, dir) > 0`.

  - The radius variant follows the same rules using `Vector3.Distance`.
